# EduLab SQL：一次准备课＋四次正式业务工单（0.9.0）

当前方案：`business-workorders/1`。使用SSMS＋真实SQL Server执行SQL，平台不模拟数据库、不让模型生成运行结果。学生前测和13题前问卷先于准备课教学。

## 学生流程

1. 完成SQL基础前测与13题前问卷。
2. 全班进入共同准备课P0，学习指定列查询、教学徒、核查复述、SSMS执行、提交与测评。P0不要求L/T分组，统一使用P角色。
3. 教师按前测完成固定L/T分组后，开展四次正式实验：学籍核查包、K01质量简报、跨班参照名单、综合验收报告。
4. 每次先看对应微课、读工单，再教学徒。教学时段结束并已发送讲解后，进入独立SSMS操作；实操开始后关闭AI。提交SQL、本人结果和核验说明后，进入独立测评。
5. 完成准备课和四次正式课的实操、测评后填写13题后问卷。准备课4题流程测评单列，正式每课10题；第4课为累计测评。题库仍需预测试，不把自动计分视作测量效度证明。

正式课默认：视频15＋读题5＋教学徒20＋实操25＋测评10＋归档5＝80分钟。准备课：前测问卷15＋流程演示10＋读题5＋共同学徒15＋实操20＋流程测评10＋归档5＝80分钟。视频由教师统一播放，可离线使用；平台没有自动核验观看完成的功能。

各环节记录本人实际用时，不自动代交。教师可按班统一控制入口；课堂实践应统一开关。开始实操前必须完成教学时段，同课不得通过“立即开放后测”跳过教学与提交。已开始环节关闭入口后仍可保存和提交，避免丢失作答；实操后AI禁止继续发言。

## 后台

原EduLab后台“当前实验控制”管理准备课和四次正式课。准备课共同提示词可编辑，正式两组只保留既定追问选择策略差异；当前工单、六个检查点与测评均按新版对应。

配置明确记录scheme_version，升级旧配置会替换当前工单和内容范围，并关闭旧开放安排，防止旧数字入口意外开放另一份新任务；实操仍默认自动模式。之后由教师保存当前开放安排。

CSV区分准备与正式，带方案版本、既往学习接触和历史基线复用标记。完整JSON保留既往档案、原对话、提示词、题目、SQL、结果、阶段时间和评分。新单选测评不接受历史SQL题评分覆盖。

## 历史与升级

0.8.x的“四课含一次准备、三次正式”、准备课L/T试运行、按知识点拆分题干和任意阶段跳转，不再作为新版当前流程。

学生升级时把旧方案完整学习记录复制到`study.scheme_history[].record`，保留原课次、组别、对话、提示词、作答和时间，不重新标记为新方案成果。已有固定组别不重新随机。已有前测和前问卷保留原时间，标记`baseline_reused_from_legacy`；有旧交互的标记`prior_scheme_exposure`，研究者应在正式分析前核对既往接触，不自动剔除学生。新一轮后问卷清除旧草稿，但旧原件在历史快照中保留。

旧试测切换指令不在新方案重放；只有带当前方案标记且设备、身份核验匹配的新指令可以切换。旧客户端不能使用新版P0入口，必须更换0.9.0。

## 部署顺序

1. 保留现有数据库、学生数据目录和0.8.x包作为升级前备份；不要删除研究数据。
2. 部署对应后台代码并执行`0027_sql_business_workorders.sql`迁移。迁移在同一事务中记录旧配置与新版本，不改写原始学生备份；迁移文件可重复运行。
3. 关闭旧学生服务，换0.9.0包，继续复用`%LOCALAPPDATA%\EduLab-SQL`。教师确认五个入口与任务正确，重新保存开关。
4. 用隔离测试身份完成P0及四个正式课的端到端演练，再向两个班统一发放。未在Windows／Win7真机与机房MDF实际数据验收前，不称已完成现场验证。

本次源码更新与本地构建不等于线上发布。Windows10/11 x64和Win7 SP1 x86/x64保留原启动器、UTF-8、Chrome95兼容、图片、自动保存和云端备份机制。打包仍使用受限客户端连接，不输出或提交`.private`、payload.zip、学生数据库或运行密钥。
