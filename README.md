# EduLab

EduLab 是一个面向教育实验研究的轻量 AI 智能体交互平台。教师可以管理多个实验，为不同组的智能体生成独立短链接。学生从对应链接进入，填写姓名（必填）和学号（选填）后获得原有规则生成的被试编号，使用服务器绑定的智能体。数据库保存开启时，每轮问题与回复及时保存，并保留浏览器副本和 JSON 导出；刷新会自动恢复，跨设备可通过原入口的“继续之前的实验”，用编号加当前姓名或学号恢复原身份。

新增“名单分层预分配”：各班按前测划三层，层内均衡分配到智能体，预览并锁定后全实验共用 `/roster/xxxx`。学生用班级和参与姓名匹配名单，无需学号；支持人工调整、锁定后补录、按最终智能体组查看和导出。原固定/随机 `/join/xxxx` 用法不变。先应用迁移至 `0017`，再新增实验即可使用名单面板；现有实验不显示此功能。详见 [名单分层预分配](docs/roster-allocation.md)。

域名首页只提示使用教师提供的完整实验链接，不提供报名或聊天入口。学生实验入口支持共享 Access Code 保护。`ACCESS_CODE` 仅保存在服务端环境变量中，验证成功后由服务端写入带签名的 `HttpOnly` Cookie，默认 7 天内无需重复输入；更换环境变量中的访问码会立即使旧验证 Cookie 失效。直接打开任意 `/join/入口码` 的未验证浏览器都会先进入访问码页面，验证成功后返回原链接。Session、消息、对话和参与者信息 API 同时要求访问码验证和分组入口，未带入口的请求不会进入默认实验。管理后台继续使用独立的管理员登录。部署到 Vercel 时须在项目环境变量中配置 `ACCESS_CODE`，修改后重新部署。

机房兼容目标为 Windows Chrome 95.0.4638.54，已显式配置旧浏览器编译目标、请求超时及 UUID 兼容路径，聊天文字可调节至 24px。验证范围和现场检查见 [机房浏览器兼容性](docs/classroom-browser-compatibility.md)。

## 技术方案

- Next.js App Router：学生页面和仅服务端可访问的 API
- Coze 官方 `@coze/api` SDK：非流式创建 Chat、轮询状态并读取最终消息
- Dify Cloud 聊天 API：SSE 流式响应、独立 conversation_id、多轮对话和请求恢复
- 标准 PostgreSQL + `pg`：Neon 可直接使用，也可迁移到任何 PostgreSQL 服务
- HttpOnly 会话 Cookie：浏览器无法读取会话密钥，修改 URL 不能读取其他参与者数据
- 独立参与者身份表：姓名、学号加密保存，通过内部 Participant ID 与交互记录关联
- 实验与分组入口隔离：每个入口独立会话，任务、规则和智能体配置随会话锁定
- 浏览器本地 Outbox 与 Session 串行发送：降低重复点击和网络中断造成的丢失风险
- Coze Chat/Conversation 标识与幂等请求及时持久化，恢复时延续原 AI 上下文
- 可折叠交互侧栏：继续既有会话，或保留身份和分组开始新一次交互；默认完整继承历史背景

## 本地启动

1. 复制 `.env.example` 为 `.env.local`，填写 PostgreSQL 和加密密钥；Coze 可使用环境 Token，Dify 应用 Key 在管理后台配置。
2. 创建数据库结构：`npm run db:migrate`
3. 临时设置 `EDULAB_ADMIN_PASSWORD`，创建管理员：`npm run admin:create -- researcher`
4. 删除临时的 `EDULAB_ADMIN_PASSWORD`，启动项目：`npm run dev`
5. 打开 `/admin` 配置实验，在“智能体与入口”中创建分组入口，复制信息和链接发给学生。

学生使用各组链接进入，先填写基本信息，提交后才生成 Participant ID，不需要研究者逐人制作链接。不同实验和智能体使用后台生成的分组链接。历史首页签名编号链接不再作为报名入口，打开后只显示链接提示；既有记录仍保留，可在后台查看和导出。

## Coze 配置

智能体必须发布到 API 渠道。国际版通常使用 `https://api.coze.com`，中国区使用与你的 Coze 账号和 Token 匹配的官方 API 地址。管理员可以在“智能体与入口”中保存多个 Bot ID；每个智能体可使用自己的加密 Token，没有单独填写时仍可使用服务器环境变量中的 `COZE_API_TOKEN`。EduLab 使用同一个 `conversation_id` 和稳定的会话级 `user_id` 维持多轮上下文。

实现依据：[Coze Chat v3](https://www.coze.com/open/docs/developer_guides/chat_v3)、[Retrieve chat](https://www.coze.com/open/docs/developer_guides/retrieve_chat)、[Personal Access Token](https://www.coze.com/open/docs/developer_guides/pat) 和 [Coze 官方 JavaScript SDK](https://github.com/coze-dev/coze-js)。

## Dify 配置

后台新增智能体时选择 Dify，填写 API Base URL（Cloud 默认 `https://api.dify.ai/v1`）和应用 API Key，无需 Bot ID。保存并测试后沿用现有实验分组和入口流程。部署前需应用 `0014_dify_agents.sql`；旧 Coze 配置和会话保持兼容。配置步骤、会话隔离、流式恢复及验证说明见 [Dify Cloud 接入](docs/dify-integration.md)。

## 管理后台

管理员从 `/admin` 登录，可以设置：

- 查看及纠正姓名、学号，保留编号、内部身份和分组，修改日志加密保存并可追溯
- 按开始时间查看被试的各次独立交互、原始消息、未发送草稿及历史加载信息
- 学生端 AI 助手显示名称和开场欢迎语（与可选任务说明独立）
- 是否提供可选任务说明（默认关闭）
- 任务标题、说明、要求、学习材料、提示和欢迎语
- 是否开放聊天、最多发送次数、每条消息字数和实验时长
- 是否及时保存消息正文及草稿到数据库，支持断点恢复
- 是否继承跨会话完整历史及首轮上下文输入预算，超出预算明确阻止发送
- 通过紧凑表格管理 Coze / Dify 智能体的内部名称、提供商、API 地址、Key 和启用状态；Coze 另需 Bot ID
- 新增或切换实验；为固定智能体或均衡随机组生成独立短链接
- 一键复制识别名称与完整链接，同时开放、暂停和继续各组报名，结束后可删除链接；有实验记录的入口码保留，确认无记录且智能体不再使用的空入口码才允许复用
- 勾选或全选参与者，批量导出数据库交互记录 ZIP；另行导出加密身份对应表解密后的 CSV
- 删除测试参与者的整组数据库记录，或删除从未投入场次使用的智能体

管理员密码使用 scrypt 哈希保存，连续失败会暂时锁定账号。Coze Token 和 Dify API Key 使用 AES-256-GCM 加密后保存到 PostgreSQL，后台不会返回明文。`ADMIN_SESSION_SECRET` 和 `SETTINGS_ENCRYPTION_KEY` 必须作为部署环境密钥长期保存。

新增实验、保存设置和智能体、创建或停止入口都会写入管理员审计记录。已有学生报名的智能体配置在停止报名或删除链接后仍锁定；API Key 可随时更新，提供商、API 地址、Bot ID、名称和启用状态保持锁定，服务端也拒绝绕过页面修改。更新 Key 后，已有会话的后续请求读取新凭证，原分组与对话上下文保持不变；后台提供“更新 Key 并测试”，新 Key 加密保存并写入不含密钥的审计记录。一个实验可同时开放多个入口；生成入口时固定已保存的任务与规则，每个学生会话再锁定分配的智能体。新入口不会关闭原入口，停止新报名也不阻止已有被试恢复。后台已移除原首页入口管理；各组使用 `/join/` 后跟 4 个字符的独立链接。复制内容只有识别名称和链接，复制成功会在按钮内提示，3 秒后恢复。已停止的入口可继续报名；确认实验结束后可删除链接，研究数据仍保留并可导出。有记录、或智能体仍被其他入口使用的旧码不释放；仅无记录且已不再使用的空入口码允许复用，生成时优先分配从未使用过的新码。各组被试编号在同一实验内统一分配，不会重复。操作说明见 [多实验与分组入口](docs/multi-experiment-links.md)。

学生端“下载全部交互记录”生成一个 JSON，包含当前项目、原分组下该被试的全部会话，以 `conversations` 分别保留会话 ID、开始/结束时间及有序原始消息。历史会话从数据库读取，换设备后无需逐条打开也能导出；当前空会话不影响下载之前的记录。正文存储被明确关闭的会话可补充本机副本，并标记可能不完整；网络或数据库读取失败时仅下载文件名含“本机备份”的可用副本，页面明确提示它可能缺少其他设备的历史记录，不声称已完整导出。姓名、学号及密钥不自动写入导出文件。正常对话仍及时保存，每节课结束可点击“提交交互记录”确认保存并下载备份，会话 ID 与时间已能区分课次。

后台批量导出的 ZIP 以 Participant ID 分文件夹，每个 Session 保存独立 JSON，消息部分与学生端各会话沿用相同格式，并附带不含姓名、学号的 `manifest.json`。清单会标记仍在进行或数据库中没有消息的 Session，提醒研究者这些实验可能仍在进行或尚未有成功保存的正文；后台可按当前实验和分组入口筛选及导出。身份对应表必须通过单独按钮导出 CSV，并再次确认其中包含敏感信息。两类导出都会写入不含姓名和学号的管理员审计记录。

删除属于危险操作：后台会弹出独立确认框，并要求再次输入 Participant ID 或智能体内部名称。删除参与者时，身份对应、Session、请求轮次、消息和智能体分配会在一个数据库事务中整体删除；对应学生页面在重新获得焦点或再次执行操作时会退出失效 Session，并清除该参与者在该浏览器中的本地对话。为了保持历史研究数据可还原，已有报名、分配、Session 或历史快照记录的智能体除 API Key 外不能修改，也不能删除，停止报名及删除入口不会解除其他配置的锁定；随机组的任一学生报名后，该组全部候选配置同时锁定。更换配置需新增智能体与入口。无记录的配置先停止相关入口报名后可以修改，确认无记录且没有未结束入口引用时可以删除。删除动作会写入不含姓名和学号的管理员审计记录。

学生端默认是对话优先界面。已有学生通过“继续之前的实验”输入原编号和当前姓名或学号登录后，会自动开启新一次交互，无需再次点击按钮；刷新、断线重连及有效 Cookie 自动恢复仍继续当前会话，不自动新建。侧栏保留查看旧会话及手动“开始新一次交互”的入口，便于同一设备保持登录时开始下一项任务。新交互保留原编号及原智能体，创建独立 Session、提供商 Conversation 和开始时间，按当前已保存的项目任务与规则重新计算本次限制；旧会话只读保留。同次交互内的多对话仍共同累计次数和时长，恢复和切换不重置原限制。不配置课次、日期间隔或班级进度。任务说明仍是可选功能，开启后可按需查看。

首次参与要求姓名、学号选填；首尾空格会被清除，重名学生独立建档。同一项目内非空学号唯一，重复时提示使用原编号恢复或联系教师，不合并记录。提交成功后沿用原 `P001`、`P002` 等编号分配规则，在同一事务内保存身份、分组和 Session；首次弹窗提醒保存编号，关闭后仅在左下角参与者信息中查看或复制。姓名精确匹配 `测试`、`ceshi` 或 `test` 的原 `T` 编号规则不变，后续身份纠正不会改变已分配编号。继续实验在服务端核验编号及当前姓名或学号，限定当前项目和原分组；原来只填姓名或只填学号的记录均兼容。身份正文及修改审计用 `SETTINGS_ENCRYPTION_KEY` 加密，平台不自动将姓名、学号发送给智能体或写入聊天记录。未提交信息时刷新不产生空记录；同一报名请求重复提交只创建一次。开场欢迎语仍只用于显示，不计入研究消息。

新交互默认从数据库加载同一被试、同一项目及原分组的完整历史，作为 Coze/Dify 首轮普通用户请求中的引用背景；不改智能体系统提示词，不复制历史消息进新 Session。后续沿用本次提供商 Conversation ID。历史来源、截止时间、指纹和预算估算保存在会话及请求中。历史缺失、变更或超过预算时明确阻止发送；后台可明确关闭继承，原始记录仍保留。部署前应用兼容迁移 `0015_repeat_interactions.sql`。操作、平台边界与验收见 [多次交互与身份管理](docs/repeat-interactions.md)。

同一台实验设备由多名学生依次使用时，已填写身份的学生可以从左下角身份信息弹窗选择“开始下一位参与者”。系统会先校验当前没有进行中的 AI 回复，并在数据库保存开启时完成当前记录整理；数据库正文保存关闭时会自动下载包含该参与者全部本地对话的 JSON 归档。随后仅清除 Participant Session，保留 Access Code 验证，下一位学生直接填写信息并获得下一个顺序编号。切换操作带有明确确认提示，不出现在主聊天工具栏。

学生端会在参与者点击发送时先同步更新当前 Session 的浏览器本地副本，再请求 AI；AI 回复到达后继续合并写入。刷新页面会同时结合本地副本与 Coze Chat 恢复双方消息，并提供 JSON 导出。导出内容包含参与者编号、Session ID、Coze Conversation / Chat / Message 标识、实验信息、严格消息顺序、对话轮次、角色、正文、发送时间、AI 回复起止时间和延迟。浏览器存储不是跨设备的中央备份，参与者清除浏览器数据后无法恢复，因此关闭数据库正文保存时必须要求参与者在实验结束前下载并提交记录。

聊天期间，学生消息和幂等请求在调用 AI 前提交数据库，AI 回复完成后与请求状态在同一事务中保存。发送成功与否由服务端确认；写入失败会提示，并保留本机尚未确认的内容。草稿在停止输入约 900 毫秒后自动保存，版本冲突不会静默覆盖。关闭、刷新或离开仍在进行的页面时仍保留原生离开确认和 Beacon 补充上传。恢复沿用原提供商 Conversation、智能体配置、限制、开始时间与结束状态，详见 [实验编号与断点恢复](docs/session-recovery.md)。

关闭“实验结束时备份完整对话到数据库”只会停止保存学生和 AI 的消息正文。PostgreSQL 仍用于参与者编号、加密身份对应表、场次分配和 Session 创建；因此数据库中断会影响进入、发送和保存操作；页面会明确提示，不能把浏览器副本当作已成功提交的研究记录。

数据库连接串不能在后台修改。它是平台最高权限凭证，仍然由 Vercel 环境变量管理；日常实验管理员不需要知道数据库账号。

## Vercel + Neon 部署

1. 将仓库导入 Vercel。
2. 在 Vercel 配置 `.env.example` 中除本地调试项之外的所有变量；`EDULAB_BASE_URL` 改为正式域名。
3. 在部署前对目标 PostgreSQL 执行 `npm run db:migrate`。
4. 建议 Neon 使用 pooled connection string，并保持较小的 `DATABASE_POOL_MAX`。
5. 在后台为各实验、各组生成短链接并分发。旧链接保留兼容，新链接统一使用 4 个字符的入口码。

数据库连接串及平台签名、加密密钥仅放在服务端环境变量中，智能体凭证也可存于原加密配置表。学生接口仅返回已认证的本身份、项目与分组记录；按参与者查询及解密身份日志仅对已登录管理员开放。

## 数据结构

- `experiments`：实验名称与管理目录，各实验独立配置及数据
- `participants`：系统自动生成或研究者预先指定的实验内编号
- `participant_identity_profiles`：与 Participant ID 一对一关联的加密姓名、学号
- `experiment_sessions`：各次独立交互及兼容的旧对话、提供商上下文、开始/活动/完成时间、草稿和历史加载信息
- `ai_agent_configs`：多个 Coze / Dify 智能体及其加密凭证
- `experiment_runs`：分组入口、短码、任务配置快照和分配规则，兼容原课程场次
- `participant_agent_assignments`：参与者、场次与锁定智能体的对应关系
- `chat_requests`：每次发送的幂等状态、对话轮次、Coze Chat 标识、失败与恢复信息
- `messages`：按会话内严格递增序号和轮次保存的学生与 AI 全量消息、角色及回复时间
- `admin_users`：管理员账号和密码哈希
- `experiment_settings`：当前实验设置、版本和加密后的 Coze 凭证
- `admin_audit_log`：设置变更、管理员登录和加密的身份修改前后记录

`database_message_storage_enabled` 默认开启并被写入 Session 设置快照。开启时每轮及时写入 `chat_requests` 和 `messages`，结束或离开时再次核对完整性；关闭时不保存正文和云端草稿，以人工下载的 JSON 为主，不能保证跨设备完整恢复。

数据库迁移是普通 SQL，运行时使用标准 `pg` 驱动，因此从 Neon 迁移到其他 PostgreSQL 服务只需迁移数据并更换 `DATABASE_URL`。

## 本地版备份与回收站

后台“本地版备份”汇总学生机轻量版、教师机局域网版已经上传的完整档案，独立于公网版 P/T 编号。

- 每页显示 50 位，按首次交互开始时间从新到旧排序，相同时间以固定标识排序，补传不改变位置。
- JSON 文件名按本次所选记录在列表中的顺序添加 `00001_`、`00002_` 等前缀，分包时序号继续递增；不改变档案内容或被试标识。
- 全选覆盖当前筛选条件下的所有页，也可单独选择本页。批量导出 ZIP 超出单包限制时自动分包，浏览器需要允许多个文件下载。
- 勾选记录可移入回收站；移入和恢复每批最多 500 位，操作前都有二次确认。
- 正常列表、单条下载及批量导出均排除回收站记录；回收站仍可查看完整对话并批量恢复。
- 回收站按设备 UUID + 参与者 UUID 保存状态。同一被试再次上传新快照仍留在回收站，恢复后显示最新备份。
- 不提供彻底删除，不修改学生机本地记录，不中断正在进行的本机交流。
- `0018_local_backup_recycle_bin.sql` 只新增状态表，不清空或改写任何原始备份；操作写入管理员审计日志。其他数据库部署需按正常迁移流程执行。

自动化数据库生命周期验证可通过显式配置 `LOCAL_RECYCLE_TEST_DATABASE_URL` 单独运行 `tests/local-backup-recycle.integration.test.mjs`；使用随机合成记录，所有测试数据和审计变更最终回滚，默认测试不会连接云数据库。
