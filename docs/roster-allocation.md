# 名单分层预分配

这是新增的第三种入口方式，仅对执行 `0017` 迁移后新建的实验开放。现有实验不显示名单面板，管理员名单接口也拒绝访问。原固定智能体、均衡随机分配及 `/join/xxxx` 用法不变，不需要为已有实验重新报名或迁移被试分组。

## 研究设计与分配

同一实验可以包含多个班级。默认各班按前测成绩降序分别划分高、中、低三层，各层人数尽量接近；同分时按教师提供的参与姓名稳定排序，因此同分学生可能跨层。分配采用确定性规则，结果不依赖文件行顺序或学生报名顺序，不属于随机分组。

每一“班级 × 层级”内优先分配给本层人数较少的智能体，再协调该班和全实验人数余数，同等条件下优先累计分数较低的组。最终实验组由智能体决定，班级、前测、层级保留为研究变量。层内人数不足或不能整除时允许空单元格或人数差异，不承诺完全相等。各班的高中低表示班内相对位置，最终起点是否接近应核对实际成绩。

后台提供各组计划人数、已进入人数、已有完成交互人数、前测均值、样本标准差、最低和最高分，以及“班级 × 层级 × 智能体”人数表与学生明细。没有学生时统计为 `—`，只有一个学生时样本标准差为 `—`。

## 教师操作

1. 先执行迁移至 `0017`，然后在后台新增实验，在其“智能体与入口”的“名单分层预分配”面板选择至少两个已经配置的智能体。
2. 下载 CSV 模板，或粘贴带表头的表格。必填列：`班级`、`参与姓名`、`前测成绩`。支持 UTF-8 CSV、TSV 和从表格复制的制表符文本，每个入口最多 5000 人。Excel 文件需先另存为 UTF-8 CSV。
3. 同班重名请在导入前改为“张三1”“张三2”等，并告知学生准确填写。跨班同名通过班级区分。“班级 + 参与姓名”必须唯一，首尾空格忽略。
4. 可选列 `层级` 只接受“高”“中”“低”；同一个班全部填写或全部留空。留空才按班内排名三等分。已经保存的草案会导出带层级的内容；需要按新成绩重新划层时，请清空对应班级全部层级再生成。
5. 默认系统生成分配。已有完整人工方案时，增加 `智能体`（后台内部名称）或 `agentId` 列，并勾选人工分配。两个列同时存在时优先使用 `agentId`。
6. 点击“保存草案并预览分配”。检查各组人数和成绩，必要时在明细中逐人调整智能体，然后保存人工调整、重新核对预览。
7. 点击“锁定方案并开放入口”，在页面内确认。存在未保存修改时不能锁定。锁定时固定当前已保存的任务与规则，并保护所有候选智能体的条件配置；API Key 续期仍沿用现有更新方式。
8. 复制统一入口，形式为 `/roster/xxxx`，复制内容标注“名单分层预分配”。同一实验的所有班级共用此链接，每个实验最多一个未删除的名单入口。旧两种入口仍可并行使用。

已锁定的名单不允许整表覆盖或重新分配。缺席、进入顺序和重复登录均不改变原分配。可以停止或继续新报名；停止后已有学生仍可恢复及开始新交互。确认研究结束后可输入入口码删除链接，原数据和历史导出保留，旧码沿用原保护规则。

## 学生进入与恢复

新链接同样需要原网站访问码。首次进入后选择班级、填写名单中的参与姓名，不需要学号，不选择层级或智能体。匹配成功后才创建原规则的 P/T 编号及 Session，并绑定预分配智能体。匹配不到明确拒绝，不创建自由报名，也不随机回退。

姓名用于名单匹配，核验强度有限。平台不会仅凭姓名恢复已有对话：已报名学生在新设备选择“继续之前的实验”，使用原编号和当前姓名恢复。忘记编号由教师查询。身份更正继续使用原有后台功能，原名单中的参与姓名作为分配依据保留；恢复使用更正后的当前姓名。

刷新、换设备恢复、新一次交互都保留原被试和智能体。不同入口 Cookie 仍隔离。误将名单入口码拼在 `/join/` 后会跳转正确的 `/roster/` 页面；普通固定/随机入口码不能在 `/roster/` 页面使用。

## 锁定后的补录与导出

“补录新学生”只新增名单行。必须明确提供新学生的班级、参与姓名、成绩、层级和已选智能体；先展示补录预览，再确认提交。已有身份冲突、版本陈旧、智能体不属于方案或成绩无效时拒绝，已有学生不重新划层或换组。补录后刷新学生链接才能加载新班级。

选择最终智能体组，可以查看学生明细并导出该组名单/分配/参与状态 CSV、交互 ZIP。名单 CSV 包含直接身份和成绩，导出前页面提示确认；交互 ZIP 复用原匿名研究记录格式，每次会话独立保存，一次最多 500 位已进入的参与者。CSV 包含方案版本和规则，可与被试编号对应。未进入学生也保留计划分配，不能把计划人数当成实际样本量。

## 存储、兼容和发布

迁移 `0016_roster_allocation.sql` 扩展分配方式约束并新增 `roster_entries` 表和相关索引，不删除、不重新编号、不修改历史会话或分组。名单姓名与成绩用现有密钥加密，匹配索引用带密钥 HMAC；班级、层级和智能体保存在服务端。草案版本和加密分配快照、锁定、补录及导出写入管理员审计。原有环境变量和密钥继续使用。

迁移 `0017_experiment_roster_visibility.sql` 为实验增加 `roster_enabled` 标记：迁移时已有实验为 false，未来创建的实验默认 true。重复执行不会重置标记，也不依据实验名称或学生人数猜测。请先迁移、再创建需要名单功能的新实验；迁移前已创建的实验仍按旧实验处理。

名单数据不进入学生页的完整名单载荷、任务快照或 AI 背景；学生页面只接收班级选项和自己的普通会话信息。姓名匹配、行认领、被试编号、智能体绑定和 Session 创建在同一事务内完成；重复身份并发只有一次创建成功，同一次报名请求重试复用结果。

开发与发布复核仅对独立本地临时数据库执行迁移，不修改 `.env.local` 指向的业务数据库。启用名单功能前，需要先对目标数据库运行原迁移脚本：

```sh
node --env-file=.env.local scripts/migrate.mjs
```

在项目根目录执行，先确认 `.env.local` 的 `DATABASE_URL` 指向目标数据库；线上使用功能时，应是 Vercel 当前使用的同一个 Neon 数据库。脚本自动跳过已执行的迁移，按顺序执行尚未应用的文件（包括 `0016`、`0017`），无需手动逐条运行 SQL，无需新增环境变量。建议在没有课堂实验进行时操作，并先确认数据库备份可用。

新代码兼容先发布、后迁移的顺序：迁移前所有实验默认隐藏名单面板；缺少名单表或新标记时，管理员名单接口返回 `ROSTER_MIGRATION_REQUIRED`，不影响已有固定/随机入口及 Coze/Dify 对话。迁移完成后新增实验即可使用名单功能。
