# 0.13.2：Win7本机版与Vercel线上版

机房目标为Windows 7 64位、Chrome 69.0.3497.81。保留当次任务、固定L/T、6/12轮、前台累计计时、精神努力、独立实操、测评和研究导出规则。

## 线上入口

https://edulab.dacnote.com/sql-student

输入原网站访问码，再选2531或2532和姓名。入口、访问码表单和学生界面使用普通HTML及ES2017脚本，不加载Next/React的现代浏览器运行时。脚本复用本机版界面及Chrome69兼容层。

线上版不需要运行EXE、Python或本机服务。学生数据存入云端会话表，按浏览器的HttpOnly设备Cookie和个人会话令牌隔离；仅知道姓名不能读取另一浏览器中的档案。相同浏览器再次登录同班同名可续做，清除浏览器Cookie或换电脑会成为新的档案，不会凭姓名公开恢复旧数据。

线上版共用现有后台的当前任务、模型、分组、人工评分、纸笔D1和ENA导出。关键提交、对话和组别变化写入原有备份档案；教师仍在同一个后台查看。API不返回模型密钥、教师答案或测评答案键。模型使用完整响应传输，仅对已完成空回复或明确临时HTTP拒绝做有限恢复，不自动重放中断生成。

## 本机包

完整解压0.13.2 Win7 x64包，先关闭旧服务窗口。

1. 优先双击`Start-Classroom.cmd`。它直接运行包内Python，绕过EXE启动器，并先显示ASCII启动信息和运行库检查结果。
2. 也可使用`EduLab-SQL.exe`。新版先显示启动阶段，确认Python已启动浏览器后才最小化，启动错误会保留在窗口中。
3. 包内保留完整`runtime`目录，不要只复制EXE或CMD。默认使用空闲本机端口，避免固定47850端口占用。
4. 运行库检查日志：`%LOCALAPPDATA%\EduLab-SQL\bootstrap.log`。Python启动日志：同目录`startup-diagnostic.log`。若仍失败，可直接使用线上入口，并提供日志排查。

“黑窗口完全无文字”尚不能定位到具体系统故障。新包提供绕过入口和可观察日志；不能据此声称已在真实机房修复。Win7仍需满足包内Python的SP1、UCRT与系统更新要求，程序不会自动改系统或下载DLL。

## 课堂与研究记录

后台只为每班选择当前课次，不设置开放和截止时间。两种入口执行相同的题目、测量与组别策略。正式研究尽量让同一学生持续使用同一种入口与同一浏览器；本机SQLite进度不会自动搬到网页会话。切换方式时先由教师核对档案，避免重复前测和重复计入。完整档案用`delivery_mode`标识线上或本机，其他历史档案保留原标记。

测试身份继续排除正式分组，完成前测、问卷后自动获得学徒。后台可重置测试课堂；正式学生不得通过试测入口切课或改组。

## 部署与验证

执行0032迁移创建云会话表；不删除旧档案，不向Windows受限数据库角色开放云会话表。构建时生成Chrome69静态资源。正式Vercel发布后还需检查入口、静态脚本、访问码和API权限。

自动化测试覆盖流程、当前任务、暂停计时、轮次、量表必答、移除成绩估算、重试、答案隐藏和云端会话隔离。另做真实模型、浏览器和持久化联调。Chrome69语法检查不能替代实际Win7机器验收；新版先在一台机房电脑验证，再统一发放。

技术依据：[Vercel函数文件系统与运行时](https://vercel.com/docs/functions/runtimes)、[Next路由处理器](https://nextjs.org/docs/app/getting-started/route-handlers)。

0.13.2 将 SDK 14393 UCRT 的41个DLL内置到两个入口的Python目录中，解决机房截图中的 api-ms-win-crt-runtime-l1-1-0.dll 缺失。无需安装MSU、修改System32或重启电脑。Windows端实际运行仍需机房复测。

0.13.2 将本机页面 Referrer-Policy 和 fetch referrerPolicy 统一为same-origin，并将fetch模式限定为same-origin，修复本机登录来源误拒绝。UCRT随包部署和课堂测量规则均保留。
