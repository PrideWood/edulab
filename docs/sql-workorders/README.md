版本：0.9.0，方案标记`business-workorders/1`。当前方案为一次全班共同准备课P0与四次正式实验，不再沿用旧三轮正式方案。

## 变化

- P0独立存储索引4，正式T1—T4索引0—3；显示顺序为P0、T1、T2、T3、T4。旧准备课索引3不再与新T4混用：旧轮次连同原任务、提示词、作答和时间保存在scheme_history，旧云备份保持原样。
- 准备课只需完成前测和前问卷，全班同P角色，不要求分组。四次正式课需要L/T分组和已完成的准备课。试测账号可由后台明确选择单课，指令只对核验身份生效。
- 当课AI教学→SSMS独立实操→独立测评；开始实操后关闭AI。未发送讲解、教学时段未结束、未提交实操时，不能跳到下一环节。已开始的实操、测评关闭入口后仍可保存与提交。
- 当前任务和六个检查点对应学籍核查、K01课程质量简报、跨班名单、综合验收。不展示正式SQL答案，不以AI代替数据库执行。
- P0为4道流程题，正式每课10道单选题；T4为累计测评。新开始轮次冻结题目、配置、任务与版本。已有单选成绩不会被旧SQL编写题评分覆盖。
- CSV明确区分准备、正式和历史，记录方案、旧接触及基线来源；完整JSON保留scheme_history。实际用时与结果正确性需联合解释。

## 部署

1. 备份生产数据库与学生机`%LOCALAPPDATA%\EduLab-SQL`。构建包不包含学生数据。
2. 更新后台代码与`0027_sql_business_workorders.sql`迁移。升级关闭旧课堂入口，避免旧开关误开新任务。迁移幂等，保留旧配置、审计、分组与原始备份。
3. 分发0.9.0对应系统版本，先关旧服务后启动。不要同时运行旧新包。旧客户端无法识别新的准备课，不能只改后台而不换客户端。
4. 教师在后台检查P0与四个工单、共同提示词和时长，重新保存开放安排。先开前测、前问卷，再开P0；共同准备课完成后，按前测分组，再依次开正式课。
5. 使用独立的虚构测试身份先做P0，再进行四次正式课。测试包括重启恢复、阶段锁定、实操提交、无AI后测、后问卷、云端记录与CSV/JSON对应；两个班使用同一版本。

本次只做本地源码修改与构建，不自动发布后台，不自动执行云端迁移，不修改生产分组或实验记录。回退不能只换旧EXE：已升级的本机数据库包含新索引，须先保留新档案，再由研究者从升级前备份恢复成套客户端、配置与数据。不得直接删除新档案。

## 历史基线

已有前测、前问卷和固定组别不自动清空或重新随机。旧轮次先完整归档，再创建新方案空轮次；旧后问卷和草稿从当前方案移出，但历史快照中保留原件。复用历史基线会被标记，已有旧交互会显示既往接触提示。研究者需检查这些记录是否适合纳入新的正式研究；软件不自动删除或剔除任何学生。
