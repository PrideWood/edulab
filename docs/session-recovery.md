# 实验编号与断点恢复

## 编号与身份

继续使用原有 `participants.external_code`：普通被试为 P001 起，姓名精确匹配“测试 / test / ceshi”的测试被试为 T001 起。保留原有最小可用编号分配算法、按实验及前缀的事务级 advisory lock 和 `(experiment_id, external_code)` 唯一约束。恢复不调用编号分配或随机分组函数。

编号不占据交互区，也不主动弹出提醒；可随时点击左下角参与者信息，在信息弹窗中查看和复制编号。首次录入要求学号，姓名可选；服务端去除首尾空格，保留历史姓名单项记录的恢复能力。初始信息弹窗区分“首次参加实验”和“继续之前的实验”。恢复使用编号和原学号；原记录未填学号时使用原姓名。仍保留网站访问码。身份保持在原来的加密身份表中，不新增明文身份字段。编号不存在与校验错误统一提示，不透露他人姓名或对话；每个实验内的编号 15 分钟最多尝试 5 次（包含成功尝试）。

## 状态与上下文

复用 `participants`、`participant_identity_profiles`、`participant_agent_assignments`、`experiment_sessions`、`chat_requests` 和 `messages`。原始配置快照、场次/智能体、会话开始时间、交流次数、结束状态及多对话列表均保留。任务说明从该会话的配置快照恢复。当前项目没有独立问卷、测验或可编辑的任务阶段模块；本次没有新增这些模块。

`participants.metadata.resume_session_id` 记录当前选择的对话；历史记录缺少该信息时恢复最后活跃的会话。输入框草稿属于每个对话，保存在 `experiment_sessions.draft_text / draft_revision`。草稿在停止输入约 900 毫秒后保存，只在内容变化时写入；网络恢复和定时检查仅重试未保存的内容。本机保存未确认的输入作为备份。草稿更新发生冲突时保留输入并让被试选择“保存当前草稿”或“使用云端草稿”，不会静默覆盖另一窗口的内容。

AI 调用继续使用原 `coze_user_id`、`coze_conversation_id` 和 `auto_save_history: true`，沿用原智能体的 Bot ID 与对应服务器凭证。历史会话缺少 conversation ID 时优先从已持久化的请求记录修复。若已有回复但完全没有上下文标识，拒绝以空白上下文恢复并提示联系教师。

恢复只更新已有会话族的随机凭证，旧设备凭证失效。被试行锁与各写入事务使用同一把锁，避免旧窗口在恢复成功后继续覆盖记录；草稿使用版本比较保护同一浏览器的多标签页。恢复次数与最后恢复时间记入已有会话 metadata。不会把恢复当作新的实验或重置交流限制。分组链接只恢复同一实验、同一入口的记录，不能借恢复切换智能体；不同链接使用独立 Cookie，浏览器记录包含实验标识。

## 消息保存与异常

学生消息及幂等请求 ID 在调用 AI 之前提交数据库；AI 回复和请求完成状态在同一事务中保存。回复写入失败时保留处理中请求及 provider ID，下次 GET 继续获取并提交原回复。消息按服务端序号恢复，唯一约束和请求 ID 防止重复插入。新会话用 `metadata.transcript_authority = server` 标记来源；浏览器上传不能制造一个服务端没有确认的轮次。历史浏览器导入机制仍兼容既有记录。旧的加密 runtime Cookie 在数据库认证通过后导入已知 provider ID，随后退出仅依赖 Cookie 的学生对话路径。旧 Cookie 中已知的交流次数也会留下计数基线，新请求继续累加，后续导入旧记录不重复计数。

AI 创建与数据库提交属于两个外部系统：如果 AI 已接受请求，但创建响应或 provider ID 保存失败，结果可能无法确认。系统保留用户记录、标记 uncertain、提示教师核验，不自动重发，也不显示成功保存 AI 回复。已持久化 provider ID 的生成中断可直接恢复，无需新建聊天。

已完成会话再次恢复仍为 completed；重复完成操作不改变完成时间。原“开始下一位参与者”仍表示结束当前被试，不是断点退出入口。

## 历史兼容与配置

迁移 `0010_session_recovery.sql` 只新增草稿字段与 `participant_recovery_attempts` 限流表，不清空、重新分组或覆盖旧记录。当前工作环境连接的数据库已经执行该迁移。其他部署指向不同数据库时，发布代码前使用已有迁移命令：

```sh
node --env-file=.env.local scripts/migrate.mjs
```

无需新增环境变量。继续使用已有 `DATABASE_URL`、`SETTINGS_ENCRYPTION_KEY`、Coze 配置及网站访问码。保持原加密密钥稳定，否则旧身份与凭证无法解密。

原来明确禁用数据库对话存储的实验不会被强制改为启用；页面明确提示下载记录，拒绝声称能跨设备完整恢复。若课堂要求完整恢复，应在开始新实验前使用已有后台设置启用数据库存储。已存在但缺少身份、配置快照或必要 AI 上下文的旧记录需教师核验；从未保存到数据库且浏览器备份也已丢失的内容无法凭编号重建。
