# 40–50 人课堂使用：加固与验证记录

检查日期：2026-09-20。本次没有调用真实 Coze API，没有验证学校网络或 Vercel 线上端到端容量。

## 本次改动

- 固定场次分配由排他锁改为共享锁；均衡随机分配仍按场次串行核对人数。不同实验的入场互不共享编号锁。
- 新被试先在事务内写入临时 UUID 编号，完成身份、分组与会话创建后，才短暂锁定并分配正式 P/T 编号，随后提交。临时编号不会提交；异常整体回滚。保留当前独立 P/T、填补空缺、唯一约束的规则。
- 数据库池默认仍为 5，排队连接超时改为 60 秒；设置语句/闲置事务超时，捕获闲置连接断开事件。入场、检查点、结束和切换参与者路由支持最长 120 秒。
- 学生消息创建得到 Coze Chat/Conversation ID 后立即返回，不再在同一个服务端请求中等待整段生成。浏览器按渐增间隔加随机抖动查询；暂时查询失败保留 ID，不重复创建 Chat。五分钟后停止自动查询并提示恢复。
- 正常运行态发送、查询不访问 PostgreSQL。身份入场、读取配置、切换会话和显式提交等操作仍需数据库；不能理解为整个网站完全不依赖数据库。
- 同页同步防重复点击；保留最近已完成请求用于重取结果；未知结果不再自动重发。加密 HttpOnly 会话 Cookie 使用紧凑格式，较大内容分片，兼容旧格式；清理时一并清除分片。
- 新增“提交交互记录”：提交该参与者本机可用的全部会话，按完整轮次分块，每块约 512 KB，等待服务端确认，临时失败有限重试。下载入口保留。
- 自动达到限制、开始下一位参与者前先分块提交，再核对消息数量和用户/AI 对应关系。最终确认不再返回完整大体积历史。
- transcript 写入改为批量 SQL；同一会话上传串行化，重复提交幂等，旧快照不能把 completed 降级；顺序冲突不静默丢弃。
- 本地存储失败显示提醒。关闭页上传只对小记录尽力尝试，不把浏览器排队成功当作数据库已保存。

## 真实 Neon 测试

执行：

```sh
node --env-file=.env.local scripts/classroom-db-check.mjs
node --env-file=.env.local --test tests/*.test.mjs
npm run lint
npm run build
```

数据库压测建立随机命名的隔离 schema，应用真实迁移、调用实际编号/加密身份/分配/记录入库函数，完成后只删除该 schema。**不要删去脚本的事务内 SET LOCAL search_path**：Neon pooled URL 不保证跨事务保留普通 SET。

每轮同时启动 50 个 Promise，连接池最多 5 个连接。计时含客户端连接池排队和 SQL 网络往返；入场脚本覆盖核心事务，不包含完整 HTTP、网页渲染、配置预读及 Cookie 返回的耗时，也不是 50 台浏览器的端到端压力测试。

| 场景 | 全部完成 | 中位等待 | P95 等待 | 结果 |
| --- | ---: | ---: | ---: | --- |
| 固定智能体，50 人入场 | 17.22 秒 | 9.84 秒 | 16.54 秒 | 50/50 成功 |
| 均衡随机，50 人入场 | 45.34 秒 | 23.98 秒 | 43.54 秒 | 50/50 成功 |
| 50 人各提交 20 轮 | 13.06 秒 | 7.75 秒 | 12.93 秒 | 2,000 条消息完整 |

合计 100 位合成被试、100 条身份映射、100 个会话、100 个唯一编号；无临时编号残留。共 1,000 个完成轮次，用户消息关联缺失为 0。同一会话并发重复上传、用户单边旧快照上传后，消息数量仍正确，状态没有降级。

第一次固定场次测试（编号锁仍覆盖整个事务）约 49 秒；缩短锁范围后的独立复测分别约 17.93 秒和 17.22 秒。以上只是当前本机到 Neon 的实测，不是线上时延保证。

## 需由研究者操作

1. 将本次代码部署后再验证；本地修改不会自动更新线上。本次没有新增数据库迁移或必填环境变量。
2. Vercel 确认开启 Fluid Compute，数据库相关函数能使用代码声明的 120 秒时限；尽量选择靠近 Neon 的函数区域。官方限制说明：[Vercel Functions limits](https://vercel.com/docs/functions/limitations)。未开启 Fluid 的旧方案可能不支持该时限。
3. 运行时 DATABASE_URL 使用 Neon 控制台的 pooled URL，DATABASE_POOL_MAX 先保持 5。不要为每位学生配置一个连接池或盲目扩大到 50。迁移可以使用 direct URL；本次不要求改动数据库结构。确认 Neon 余额/算力与连接额度。
4. 检查 Coze 当前空间的套餐、可用积分、模型/接口限额，确保课堂前 Token 有效，智能体已发布。付费套餐不等于没有限流；多个 Bot 也不应当作独立额度池。此次未消耗 API 做真实并发验证。
5. 正式课前使用测试姓名、独立测试场次，在学校实际设备/网络做 5 人、20 人，再 40–50 人试运行，检查入场时间、429/502/504、回复完成率、下载内容与后台消息数。每个参与者只开一个聊天标签页。
6. 收课时要求点击“提交交互记录”并看到确认，或由实验人员下载记录收集；不要只要求直接关网页。均衡随机入场比固定场次慢，应预留时间；当前课堂统一智能体优先用固定场次。

## 仍不能承诺的边界

- 浏览器崩溃、强制退出、断电、系统杀进程时，beforeunload/pagehide 不一定执行；本地存储也可能被清除。不能保证“关页一定上传”。离线未确认的内容仍需保留本机下载备份。
- 创建 Coze 请求已经成功、但返回 ID 的响应完全丢失时，纯 Cookie 架构无法证明请求是否执行。跨设备/多标签/恶意并发也不具备全局 exactly-once 保证。本次降低正常重复发送风险，但没有引入额外 Redis/持久化请求队列。若要消除此窗口，需要另行选择共享协调存储及其延迟/成本取舍。
- 超过单轮分块上限或浏览器存储额度时会报错，需下载人工收集；不会静默宣称云端保存成功。
- 编号空缺复用是现有需求，历史导出必须以内部 UUID / Session ID 对应，不能仅靠可复用的 P/T 展示编号跨批次匹配。

本次结果支持继续进行真实课堂预演，不等同于已经验证 Coze + Vercel + 学校网络全链路可承受 50 人。
